# smb-mount-healer

Kubernetes operator that detects and heals broken SMB/CIFS CSI mounts (csi-driver-smb): per-node worker probes, leader-elected control plane remediation with dry-run mode, and quarantine of data written to dead mounts.

**Homepage:** <https://github.com/marcherschel/smb-mount-healer>

## What it deploys

| Object | Purpose |
|---|---|
| Deployment `<fullname>-controlplane` | Leader-elected control plane (`--controlplane`): the only decision maker. Creates `SmbMountRemediation`s, scales workloads, restarts the CSI node driver pod and creates `SmbHostTask`s. Non-root, read-only root filesystem. |
| DaemonSet `<fullname>-worker` | Privileged per-node worker (`--worker`): probes SMB mounts, publishes `SmbMount` health, runs host tasks (force-unmount, quarantine), reports `SmbQuarantine`s. Mounts `kubeletRoot` with `mountPropagation: Bidirectional`. |
| CRDs `smbm`, `smbr`, `smbt`, `smbq` | `smbhealer.herschel.io/v1alpha1`, cluster-scoped. Templates (not `crds/`), so upgrades update them; `crds.install` toggles them, `crds.keep` protects them from `helm uninstall`. |
| ClusterRoles, bindings, ServiceAccounts | ClusterRole rules are generated from the code's RBAC markers (`hack/sync-chart.sh`). |
| Role/RoleBinding `<fullname>-leader-election` | Lease and Events in the release namespace (only with leader election). |
| Services `<fullname>-{controlplane,worker}-metrics` | Port `http-metrics` (8080, `/metrics`); the worker Service is headless. |
| PodMonitors (optional) | `metrics.podMonitor.enabled`, needs the Prometheus Operator CRDs. |
| ConfigMap `<fullname>-dashboard` (optional) | `monitoring.grafanaDashboard.enabled`: the Grafana dashboard for the Grafana dashboard sidecar. |
| PrometheusRule `<fullname>` (optional) | `monitoring.prometheusRule.enabled`: the alerts, each with a runbook link. Needs the Prometheus Operator CRDs. |

## Installing

The chart does not create its namespace. The worker is privileged, so the
namespace needs the Pod Security label `pod-security.kubernetes.io/enforce: privileged`:

```sh
kubectl create namespace smb-mount-healer-system
kubectl label namespace smb-mount-healer-system \
  pod-security.kubernetes.io/enforce=privileged \
  pod-security.kubernetes.io/audit=privileged \
  pod-security.kubernetes.io/warn=privileged
```

Start in dry-run mode and watch what the healer would do:

```sh
helm install smb-mount-healer oci://ghcr.io/marcherschel/charts/smb-mount-healer \
  -n smb-mount-healer-system --set dryRun=true
helm test smb-mount-healer -n smb-mount-healer-system

kubectl get smbm,smbr,smbq
kubectl get smbr -o wide            # finished dry-run episodes show OUTCOME dry_run
kubectl get smbt -o yaml            # every planned host action, result DryRun
```

Then let it act:

```sh
helm upgrade smb-mount-healer oci://ghcr.io/marcherschel/charts/smb-mount-healer \
  -n smb-mount-healer-system --reuse-values --set dryRun=false
```

Abort a running remediation (it moves to `rolling_back` and restores replicas):

```sh
kubectl annotate smbr <name> smbhealer.herschel.io/abort=true
```

## Quick start with Flux

A minimal Flux setup that enforces right away (no dry run). It assumes
csi-driver-smb installed with its chart defaults (node DaemonSet
`csi-smb-node` in `kube-system`) and the standard kubelet directory. The
defaults were developed and tested against Talos Linux; any distribution with
the kubelet in `/var/lib/kubelet` works the same.

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: smb-mount-healer-system
  labels:
    # The worker is privileged (it unmounts and moves directories on the host).
    pod-security.kubernetes.io/enforce: privileged
---
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: smb-mount-healer
  namespace: smb-mount-healer-system
spec:
  type: oci
  url: oci://ghcr.io/marcherschel/charts
  interval: 1h
---
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: smb-mount-healer
  namespace: smb-mount-healer-system
spec:
  interval: 10m
  chart:
    spec:
      chart: smb-mount-healer
      version: 0.1.x
      sourceRef:
        kind: HelmRepository
        name: smb-mount-healer
  values:
    # Enforcing: remediations scale workloads, unmount and quarantine.
    # Set true to only detect and plan (an emergency brake, too).
    dryRun: false
    # Only needed if csi-driver-smb is NOT installed with its defaults: the
    # control plane restarts the node driver pod on the affected node, so the
    # namespace and label selector must match your csi-smb-node DaemonSet, and
    # driverName must match the PVs' spec.csi.driver.
    # csi:
    #   driverName: smb.csi.k8s.io
    #   nodeDriver:
    #     namespace: kube-system
    #     labelSelector: app=csi-smb-node
    # Only needed if the kubelet does not live in /var/lib/kubelet (the
    # default, e.g. on Talos, kubeadm, k3s, RKE2). Examples: k0s
    # /var/lib/k0s/kubelet, MicroK8s /var/snap/microk8s/common/var/lib/kubelet.
    # It must be the path on the host: the worker mounts it as hostPath.
    # kubeletRoot: /var/lib/kubelet
```

## Dry run

`dryRun: true` adds `--dry-run` to the control plane (and the annotation
`smbhealer.herschel.io/dry-run: "true"`). Remediations then walk every stage
and end with outcome `dry_run`; host tasks are created with `dryRun: true` and
the worker only reports what it would do. Nothing is scaled, deleted,
unmounted or quarantined. The worker has no dry-run setting of its own: it
follows `spec.dryRun` of each host task.

## Monitoring

Both components serve Prometheus metrics (`smb_mount_healer_*`) on port
`http-metrics`. With the Prometheus Operator (e.g. kube-prometheus-stack):

```yaml
metrics:
  podMonitor:
    enabled: true
    labels: {release: kube-prometheus-stack}   # match your podMonitorSelector
monitoring:
  grafanaDashboard:
    enabled: true            # ConfigMap for the Grafana dashboard sidecar
    # namespace: monitoring  # if the sidecar only watches Grafana's namespace
  prometheusRule:
    enabled: true
    labels: {release: kube-prometheus-stack}   # match your ruleSelector
```

| Alert | Severity | Fires when |
|---|---|---|
| `SmbMountHealerControlPlaneAbsent` | critical | no control plane has reported metrics for 30m |
| `SmbMountHealerRemediationFailed` | warning | a live remediation ended without healing (last hour) |
| `SmbMountHealerRemediationLoop` | critical | more than 2 workload remediations for one node in an hour, for 15m |
| `SmbMountHealerShadowDataPending` | warning | data written to a dead mount has waited in quarantine for 1h |

`monitoring.prometheusRule.disabledAlerts` leaves alerts out,
`additionalRuleLabels` adds routing labels, and `runbookBaseUrl` points the
`runbook_url` annotations at your own copy of the runbooks. Without the
Prometheus Operator, use the dashboard JSON and plain rule file attached to
every GitHub release (they are the same files as `monitoring/` in the
repository).

## Image

`image.reference` (a full `repo:tag@digest`) wins over `image.repository`,

## Uninstalling

With `crds.keep: true` (the default) `helm uninstall` leaves the CRDs and all
`smbm`/`smbr`/`smbt`/`smbq` objects in place. Quarantined data is never
deleted by the healer; it stays on the nodes under the quarantine directory
until you move it. Delete the CRDs by hand to remove everything.

## Versioning

The chart and the app (image and binary) are released independently from
the same repository: app releases are tagged `vX.Y.Z`, chart releases
`chart-vA.B.C`. The chart's `version` is its own SemVer, and its
`appVersion` is the app release it deploys by default (override with
`image.tag`). A chart release can ship template, values, dashboard or alert
changes without a new image. While the versions are `0.x` the API is
`v1alpha1` and may change between minor versions.
